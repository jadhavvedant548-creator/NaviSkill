# Technical viva
1. What is PS2? Community-Based Digital Literacy and Skill Development.
2. Why a website? Accessible through a browser, modular, no installation needed for standalone use.
3. Stack? HTML structure, CSS presentation, JavaScript interaction, localStorage, optional Vercel serverless Node backend and Gemini.
4. What is Virtual Digital City? A visual entry point to six existing everyday simulations.
5. What is guided learning? Learn, Practise, Check, Complete with knowledge feedback.
6. Why three languages? Reduce language barriers for local learners.
7. How does offline work? Embedded resources in standalone HTML; hosted service worker caches core files after initial successful load.
8. Is offline NaviAI generative? No, predefined topic guidance.
9. Why API key? Authorizes provider requests; stored server-side only.
10. What is access code? Shared exhibition gate, not full authentication.
11. How is scam detection implemented? Heuristic warning patterns; not proof of fraud or safety.
12. How is roadmap personalised? Deterministic recommendations from profile, skill level and progress.
13. How is improvement calculated? Final minus initial score for paired learners; average across paired records.
14. Why anonymous IDs? Reduce collection of identifying information; local storage is still not encrypted.
15. Is passport accredited? No, local learning record only.
16. How do you prevent XSS? Text rendering for new user data and AI output, validation and CSP; legacy inline scripts remain a limitation.
17. What is rate limiting? Restricts request volume; current per-instance implementation is best effort.
18. What SDGs? Primarily 4 and 10; alignment is not measured impact.
19. How tested? Node logic/mock tests, Chromium exercised flows, user regression tests on earlier versions; live V15 checks pending.
20. Future work? Community trials, distributed rate limits, stronger authentication, accessibility and device testing.
